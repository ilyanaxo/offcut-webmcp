Offcut — a shared cutting-stock workbench

Measure and protect your stock. Let your browser agent compare cutting plans. Review before releasing a cut sheet.

Live workbench: https://ilyanaxo.github.io/offcut-webmcp/
Public MIT source: https://github.com/ilyanaxo/offcut-webmcp
Use, run and test guide: https://ilyanaxo.github.io/offcut-webmcp/guide.html

Measured stock is a structured problem
Offcut is for small workshops, makerspaces and individual makers arranging straight crosscuts from boards and existing offcuts of the same material and cross-section. A maker records usable lengths and exact part quantities, sets blade kerf, and protects stock needed elsewhere. In a chat-only workflow, that state has to be copied out and the answer reconciled with the workbench. WebMCP gives the browser agent structured access to the same committed measurements and revision the maker sees. The agent requests checked alternatives; Offcut's deterministic solver, not the language model or a screenshot estimate, checks quantities and physical material balance.

Show the trade-off instead of hiding it in a waste score
People edit stock and part lists, protect individual lengths, and compare proportional layouts under three objectives. Sawdust, short scrap, reusable remnants and unopened stock remain distinct; full-reference disclosures identify the actual plans, boards and requirements.

The verified 1.1.0 illustrative job produces 14 parts totalling 7,000 mm with A-01 protected, 3 mm kerf and a 400 mm reusable threshold. Use less stock and Handle fewer boards each open 7,200 mm across three pieces: 42 mm sawdust, 158 mm short scrap and no reusable remnant. Keep useful offcuts opens 10,080 mm across six pieces: 42 mm sawdust, no short scrap and 3,038 mm reusable remnants. Avoiding 158 mm of short scrap therefore opens 2,880 mm more stock and handles three more pieces. These are computed sample results, not measured real-workshop, time, money or carbon savings; later use of the remnants is not demonstrated.

One shared workshop, from comparison to re-review
Before: a maker copying a stock list into chat has to reconcile advice with the current workshop and translate it back into a cut sheet. With Offcut: the person measures and protects stock; the agent reads that committed revision, requests alternatives, compares their explicit constraints and stages one exact complete proposal. The person checks its identities, quantities, offsets and kerf, then separately acknowledges and approves that ID. The agent can export only the exact approved fresh plan, not whichever draft happens to be selected.

If the person commits a kerf change from 3 to 4 mm, the old plan becomes stale and its approval is invalidated. The agent must read the new revision, replan and stop for a new review. Unfinished text is different: PENDING_MEASUREMENTS holds review requests until edits are finished or cancelled, without silently saving text or revoking approval per keystroke. The shared page carries the proposal-to-decision handoff and the reason an earlier decision is no longer valid; it does not reserve or consume stock.

Native tools backed by the same checked domain operations
Offcut is a static React/TypeScript application built with Vite. It registers six JSON-schema-defined JavaScript tools in the top-level page through real document.modelContext, with only the real native navigator.modelContext Chrome-149 compatibility path: get_workshop, plan_cuts, inspect_plan, compare_plans, stage_plan_for_review and export_cut_list. UI and tools share the workshop store and deterministic branch-and-bound planner. Planning and staging require the current expectedRevision; pending edits hold staging/approval, and incomplete, stale or unapproved plans cannot be released. Approval, stock unlocking and measurement mutation are absent from the registered tools. Registration readiness is not a model connection. There is no polyfill, application backend, embedded model or website API key; manual planning works without WebMCP. The model uses integer-millimetre one-dimensional crosscuts and one kerf per produced part. Search is capped at 100,000 nodes, with optimality reported only when proved. It is a planning estimate, not machine control or a safe-cutting guarantee.

Use and release the same committed job
The canonical guide linked above contains setup, source/run/check instructions and the complete output contract. Comparisons disclose protected stock separately from each plan's additional exclusions and identify same/different effective constraints for fresh complete plans. Zero additional exclusions does not mean zero protected stock.

A repeated valid request may reuse a retained checked solution at the same revision, objective and canonical additional-exclusion set. It still creates a new unapproved record ID. reusedFromPlanId identifies the actual source record; search.nodes and proof status belong to the original computation, not newly executed work. Full plan, board & part IDs and Full comparison references & restrictions are keyboard/touch disclosures of the raw stored references. Released CSV has 17 columns, with Part ID (the requirement ID) at zero-based index 8 before Part, and filenames include the full actual generated plan ID: offcut-${slug}-r${revision}-${plan.id}.csv.

While pendingMeasurements is true, human review/approval/CSV/print pause. Native export of the exact already-approved fresh complete committed plan intentionally remains allowed: it reads the saved decision, not the editor draft, and neither saves text nor grants approval. Finish or cancel all edits; reread the revision and replan if a value actually changed. Re-reviewing and rejecting the currently approved ID revokes that approval; rejecting a different draft preserves the other exact approval.

Host setup — official documentation as of September 3, 2026
Offcut requires no website login or API key; the browser-agent host has separate account, model and permission requirements. For ChatGPT Site tools, use the latest desktop app's built-in browser with Work or Codex and GPT-5.6 Sol or Terra, not Luna (WebMCP disabled). Enterprise/Edu workspaces are unsupported; availability also depends on rollout and the current page. Enable Settings > Browser > Permissions > Enable site tools, open the live workbench directly in the top-level page, and inspect Site tools > Available site tools. Normal website-access and confirmation policies still apply. The supported Chrome alternative is version 149 or later with chrome://flags/#enable-webmcp-testing enabled and the browser restarted; that flag exposes the API, not a model connection.
Official Site-tools guide: https://learn.chatgpt.com/docs/webmcp
Chrome setup: https://developer.chrome.com/docs/ai/webmcp

What is — and is not — new
Cutting-stock optimization is established work. OpenCutList already supports standard/offcut boards, blade thickness, trimming and cutting diagrams. Offcut's contribution is the shared committed workshop, explicit agent comparison, exact review/release and revision invalidation in one browser page, not a claim to invent cutting optimization or to be the first such product worldwide.
Workflow precedent, not copied code/artwork: https://docs.opencutlist.org/features/parts/parts-list/cutting-diagrams/dimensional.md

Demonstration scope and version
The current 1.1.0 demonstration uses 25 actual stateless model decisions, including 19 Chrome-native tool calls and six local finish decisions, through an external recording harness. The 165-second English-audio/40-cue video shows actual live-app pixels and clearly identified retained native/UI evidence summaries. Stock protection, navigation, acknowledgement/button approval, CSV download and measurement edits are separate browser UI automation. The video is not a ChatGPT interface recording, authenticated physical-human-presence proof or an end-to-end latency benchmark. GitHub release availability is separate from Public YouTube playback, a Submitted Devpost entry and a jury outcome.

Offcut 1.1.0 passed 884 source-contract tests and 72 executed browser cases: the same 18 contracts on each local/hosted and Chrome-149/152 combination. The maximum 40-cut export includes all 17 CSV columns and every cut; both six-page PDFs and all 12 actually rendered print pages are recorded in the portable evidence. Controlled same-problem solution reuse and aggregate browser workloads improved without transferring approval; these measurements are not model/judge latency or physical workshop savings. Exact source, native/model, CSV, final-media and publication evidence is linked in entry.json and the verification reports. Approval absent from the registered tools is a capability boundary, not authentication: trusted same-origin scripts, developer tools or an agent separately granted UI-control permission can operate the page. Retain the final UI decision outside the agent's permissions/workflow if it is to remain with the person.
