Offcut — a shared cutting-stock workbench

Measure and protect your stock. Let your browser agent compare cutting plans. Review before releasing a cut sheet.

Measured stock is a structured problem
Offcut is for small workshops, makerspaces and individual makers planning straight crosscuts from boards and existing offcuts of the same material and cross-section. The problem is arranging exact part quantities around usable lengths, blade kerf and pieces someone needs to keep. Those are explicit constraints, not measurements an agent should estimate from a screenshot. WebMCP exposes the committed workshop and checked proposals in the same page the person is using. The browser agent can request and compare alternatives; Offcut's deterministic solver, rather than the language model, checks quantities and physical material balance.

Show the trade-off instead of hiding it in a waste score
People can edit stock and part lists, protect individual lengths, and compare proportional cutting layouts under three objectives. Sawdust, short scrap, reusable remnants and unopened stock remain distinct. In the original illustrative 14-part job, all plans produce 7,000 mm of finished parts with A-01 protected, 3 mm kerf and a 400 mm reusable-remnant threshold. Use less stock and Handle fewer boards each open 7,200 mm across three pieces, with 42 mm sawdust, 158 mm short scrap and no reusable remnant. Keep useful offcuts opens 10,080 mm across six pieces, with 42 mm sawdust, no short scrap and 3,038 mm reusable remnants. Avoiding 158 mm of short scrap therefore opens 2,880 mm more stock and handles three more pieces. These are executed illustrative results, not measured customer, money or environmental savings.

One workshop, proposals from an agent, a separate release decision
The person-facing workflow owns usable measurements and protected stock; agent tools work from that committed workshop instead of a detached copy in chat. In an actual hosted run, the default session model selected 14 native calls covering all six tool types. It generated and compared three complete objective plans, inspected and staged the least-stock plan, then stopped without approval. After separate UI checkbox and approval-button actions, the model inspected and exported that exact approved plan. Committing a kerf change from 3 to 4 mm invalidated the old release. The model read revision 2, identified the old plan as stale and unapproved, and computed, inspected and staged a fresh complete 14-part plan with 56 mm of sawdust, again stopping for review. This run used actual stateless model completions and native Chrome tools; the approval and measurement edits were browser UI automation, not model tools or a ChatGPT screen recording. Approval is absent from the registered tool surface, not cryptographic human-presence authentication. No stock was reserved or consumed.

Native tools backed by the same checked domain operations
Offcut is a static React/TypeScript application built with Vite. It registers six JSON-schema-defined tools through the real document.modelContext API, with the real native navigator.modelContext surface for Chrome 149 compatibility: get_workshop, plan_cuts, inspect_plan, compare_plans, stage_plan_for_review and export_cut_list. UI and tool operations share the workshop store and deterministic branch-and-bound planner. Planning and staging require the current expectedRevision; incomplete, stale or unapproved plans cannot be released. Registration readiness is reported only after native registration succeeds. There is no polyfill, application backend, embedded model or website API key. Manual planning still works without WebMCP. The physical model is integer-millimetre, one-dimensional crosscutting with one kerf per produced part. Search is capped at 100,000 nodes; a complete bounded result is not labelled optimal unless optimality was proved. It is a planning estimate, not machine control or a safe-cutting guarantee.
