Offcut is a browser-only cutting-stock workbench for small workshops and makerspaces. It plans one-dimensional crosscuts from the usable material you already have. People and browser agents work with the same committed measurements, protected stock and proposals.

No application login, application server, model key or paid API is required by this website. The starter job is an original illustrative example, not a real customer's workshop. Verify or replace its measurements before using a cut sheet.

Use the workbench

  1. Record a homogeneous batch. Give the project a name and material/cross-section description. Add each physical board or existing offcut separately. Enter usable lengths in integer millimetres, after deducting end trim and unusable defects.
  2. Record the job. Enter finished part lengths and exact quantities. Set your blade kerf and the minimum length you consider a useful reusable remnant. This is your workshop policy, not a universal threshold.
  3. Commit edits. Press Enter or leave a field to save it. Escape cancels an unfinished field edit. Invalid or unfinished fields/new rows block human solving and release. Native tools read committed measurements, not uncommitted text in an editor.
  4. Protect stock. The protection button keeps that physical length untouched under every objective. The agent cannot unlock it through a registered tool.
  5. Find and compare proposals. Choose Use less stock, Handle fewer boards, or Keep useful offcuts. These are genuinely different objectives; a higher finished-part yield is not always less discarded material.
  6. Review an exact fresh complete proposal. Check its stock IDs, quantities, offsets, kerf and restrictions. The acknowledgement and approval are a separate UI step. No WebMCP tool is exposed for approval.
  7. Release the approved cut sheet. Download CSV or print. Both use the actual approved plan, even if a different draft is selected. Changes to committed measurements invalidate approval; reloading the page restores measurements only, not plans or approval.

There are at most 24 stock lengths, 16 requirement entries and 40 produced parts per planning batch. Approval/export do not reserve, consume or physically cut inventory. Record your actual remaining usable stock yourself for the next job.

Use your real browser agent

Open the workbench in ChatGPT's in-app browser, or a WebMCP-capable Chrome browser with a real browser-agent host. Chrome's testing flag exposes the browser API; it does not itself create or connect an agent.

For Chrome 149 or later, enable chrome://flags/#enable-webmcp-testing and restart, or launch an isolated test browser with --enable-features=WebMCP. The app uses the real document.modelContext where available, with only the actual native navigator.modelContext surface as the Chrome-149 compatibility path. It installs no polyfill.

Wait for the site's real registration status. “Native WebMCP ready” means registration succeeded, not that a particular model has connected. The activity panel attributes real UI actions and native tool invocations separately.

Physical model and honest result confidence

For every used stock length, Offcut enforces:

sum(finished part lengths) + part count × blade kerf
  + final remnant = usable stock length

Each produced part consumes one saw pass, including the last. No free final factory-end cut is assumed. At a 3 mm kerf, a 997 mm part fits a 1,000 mm usable board; a 1,000 mm part does not fit under this conservative policy. It is not a universal model of every possible end-cut convention.

Positive remnants at or above your threshold are reusable; shorter positive remnants are short scrap; zero is neither. Waste is sawdust plus short scrap. Unopened stock is not waste. For a fixed complete job and kerf, modelled sawdust is constant, so the meaningful trade-offs are stock opened, stock pieces handled and remnant distribution.

The deterministic branch-and-bound search is limited to 100,000 search nodes. “Optimal for this objective” is reported only after valid exhaustive search/pruning with a complete result. At the limit, a feasible plan remains a feasible plan with optimality unproved. Failure to find a complete plan under a search bound is not a proof of infeasibility. Partial proposals identify missing quantities and cannot be approved/exported.

This is a planning estimate, not machine-control, a certified design, or a safe-cutting guarantee. It does not model angled cuts, grain matching, clamping, rough-board defect placement or different material sections. Verify stock identity, usable measurements, actual blade kerf and safe workholding at the bench.

A demonstrated trade-off, not an invented savings claim

For the illustrative 14-part job, with A-01 protected, 3 mm kerf and a 400 mm reusable-remnant threshold, the executed planner found:

Objective Stock opened Stock pieces Sawdust Short scrap Reusable remnants
Use less stock 7,200 mm 3 42 mm 158 mm 0 mm
Handle fewer boards 7,200 mm 3 42 mm 158 mm 0 mm
Keep useful offcuts 10,080 mm 6 42 mm 0 mm 3,038 mm

All produce the same 7,000 mm of finished parts and keep A-01 untouched. The last plan discards 158 mm less short scrap, but opens 2,880 mm more stock and handles three more lengths. Those are scenario-specific computed results, not measured workshop-wide, money or carbon savings.

Run the source

Source: github.com/ilyanaxo/offcut-webmcp. The project is a static React/TypeScript application built with Vite. Use Bun 1.4 or later; the tested Node runtime meets the package's Node 22.12-or-later requirement. 

git clone https://github.com/ilyanaxo/offcut-webmcp.git
cd offcut-webmcp
bun install --frozen-lockfile
bun run build
bun run preview

The production preview is http://127.0.0.1:4173/. For development, bun run dev uses http://127.0.0.1:5173/. No environment secrets are required. Deploy the generated dist/ directory to static HTTPS hosting; relative asset URLs support a project subdirectory.

Run observable-contract checks

bun run test
# Keep the production preview running, then in another terminal:
bun run test:browser
bun run format:check

Browser tests use installed Google Chrome with its sandbox enabled. CHROME_PATH can select a different installed Chrome executable; OFFCUT_BASE_URL can target your HTTPS deployment. The suite does not secretly start a server or install a native-API polyfill. Native and ordinary/manual browser projects are separate.

Browser-test temporary profiles default to .cache/browser-tests in the project. An explicit TMPDIR overrides this location. On systems with per-user quotas on /tmp, choose a private directory on a filesystem with enough actual quota headroom, not just globally reported free space.

The tests defend physical feasibility/quantities/accounting and all three objectives against independent exhaustive small-instance assignments, actual bounded-search behavior, revision/approval transitions, persistence, CSV content and the real browser surface. Native registration/discovery/execution were exercised in Chrome 149.0.7827.155 and 152.0.7977.64. This is not a claim that a ChatGPT in-app-browser window was visually exercised.

Data, rights and implementation references

Validated measurements are saved in localStorage on this site's origin when available. Plans, approvals, activity and native registration last for the current page session. The website has no application backend or model calls. A browser agent receives tool results and may process them under its provider's policies; hosting/browser policies also apply.

The application source and original visual/example assets use the repository's MIT license. Runtime dependency copyrights and licenses are preserved in THIRD_PARTY_LICENSES.txt. No customer data or copied workshop photographs are used in the illustrative example.
