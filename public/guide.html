Measure your stock.
Let an agent arrange.
Keep the final call.

Offcut is a browser-only cutting-stock workbench for small workshops and makerspaces. It plans one-dimensional crosscuts from the usable material you already have. People and browser agents work with the same committed measurements, protected stock and proposals.

No application login, application server, model key or paid API is required by this website. The starter job is an original illustrative example, not a real customer's workshop. Verify or replace its measurements before using a cut sheet.

Use the workbench

  1. Record a homogeneous batch. Give the project a name and material/cross-section description. Add each physical board or existing offcut separately. Enter usable lengths in integer millimetres, after deducting end trim and unusable defects.
  2. Record the job. Enter finished part lengths and exact quantities. Set your blade kerf and the minimum length you consider a useful reusable remnant. This is your workshop policy, not a universal threshold.
  3. Commit edits. Press Enter or leave a field to save it. Escape cancels an unfinished field edit; complete or cancel new rows too. Pending fields or rows block human solving, review, approval and release. Native planning still reads committed measurements, not uncommitted editor text. See the pending-measurements policy below.
  4. Protect stock. The button reads Available or Protected and keeps that physical length untouched under every objective when protected. Its accessible name also states the action, label and ID, for example “Available — protect stock Long board (A-01)”. A pressed Protected button means protection is on. No registered tool can unlock it.
  5. Find and compare proposals. Choose Use less stock, Handle fewer boards, or Keep useful offcuts. These are genuinely different objectives; a higher finished-part yield is not always less discarded material.
  6. Review an exact fresh complete proposal. Check full plan, stock and part IDs, quantities, offsets, kerf and restrictions. Expand the full-reference disclosure with a keyboard or touch; the numerical cut tables, not tiny strip labels, are the cutting reference. Acknowledgement and approval are separate UI actions. No WebMCP tool approves.
  7. Release the approved cut sheet. Download CSV or print only after edits are finished or cancelled. The release panel identifies the saved approved plan separately from the selected draft. Selecting or generating another proposal, including a reused solution with a new ID, does not transfer approval. A real committed measurement change invalidates approval; reloading restores measurements, not plans or approval.

There are at most 24 stock lengths, 16 requirement entries and 40 produced parts per planning batch. Approval/export do not reserve, consume or physically cut inventory. Record your actual remaining usable stock yourself for the next job.

Committed measurements are not unfinished editor text

pendingMeasurements is one shared UI/store/native flag: it is true while at least one field or new row has an unfinished edit. It is ephemeral, is not saved with your measurements and does not itself change the workspace revision, activity or saved approval. Merely focusing an unchanged field is not an edit. Typing does not revoke approval on every keystroke. Editors report their combined unfinished-field/row state through the store's setPendingMeasurements(boolean); no native measurement-mutating tool is added.

While the flag is true, an otherwise valid stage_plan_for_review request returns ok: false with error.code: "PENDING_MEASUREMENTS" before publishing review. It does not open a dialog, blur a field, save text or approve anything. Approval is also held. Workshop and plan descriptions report the flag; canRequestReview requires a fresh complete plan and no pending measurements. Existing plan-ID and revision guards still apply.

Finish or cancel all edits, then read get_workshop again. If a saved value actually changed, use the new revision to replan before requesting review; old plans are stale. If the value did not change, the revision stays the same and a still-fresh plan can be staged. For example, textual 03 remains a draft until saved or cancelled, even when the committed kerf is already 3 mm. Cancelling one of two unfinished fields does not clear the other field's hold.

Intentional committed-export policy: human CSV/print controls pause during pending edits. Native export_cut_list may still return the exact already-approved, fresh, complete committed plan while editor drafts exist. It reads the approved saved decision, not those drafts, and neither saves measurements nor grants approval. An actual committed change invalidates that release for both paths.

Compare explicit constraints, not just objective names

Protected stock applies to every proposal. A plan's excludedStockIds are additional exclusions for that proposal, not the total protected stock. “0 additional exclusions” can therefore coexist with a protected A-01. The effective unavailable set is the union of protected and additional IDs, counted once per physical stock ID.

Native comparison accepts two or three distinct fresh complete plans for the current job. It returns protectedStockIds and sameConstraints, plus each row's canonical additional excludedStockIds and sameConstraintsAsFirst. These indicators compare effective sets: adding an already-protected ID does not change the allowed stock. Different constraints remain useful for what-if comparisons, but then a metric difference cannot be attributed to the objective alone. Open Full comparison references & restrictions for the raw IDs and canonical sets. Indicators qualify fresh complete comparable plans; do not combine today's protection with a stale historical proposal's basis.

Review identity and dialog decisions

Open Full plan, board & part IDs for actual plan, used-board and requirement IDs (and the reuse source where present), without hover-only tooltips or renumbering aliases. Use Tab to reach the disclosure, Enter or Space to open it, or tap it. Duplicate human labels do not make two physical boards or requirements interchangeable. Timestamps follow the browser's local time zone; IDs and workspace revisions, not displayed time labels, identify a decision.

A different plan staged into an open review resets acknowledgement and returns focus to the review heading. Re-staging the same ID is not a new decision. Reject proposal, closing review without approval or Escape rejects the staged plan. If you re-review the currently approved ID and reject it, that approval is revoked; rejecting a different draft preserves the other exact approved plan. If review interrupts a sample/clear confirmation, that confirmation resumes after review closes. Dismissing it returns to the original sample/clear control. These are native browser dialogs, not a custom strict Tab-wrap trap.

Released CSV identity and columns

The filename is offcut-${slug}-r${revision}-${plan.id}.csv: the project slug, committed revision and full actual internally generated plan ID. Different approved plans at the same revision therefore have distinct filenames. It is not a shortened reference or a new approval alias. The CSV has one row per produced part, with all rows retained up to the 40-part batch limit.

There are 17 columns in this order (line breaks below are only for readability). The new ninth column, Part ID at zero-based index 8, contains the requirement ID cut.requirementId, before the human-readable Part label. This distinguishes duplicate part labels; Part instance distinguishes repeated pieces of that requirement. 

Project | Material (same cross-section) | Plan ID | Workspace revision
Board ID | Board label | Usable stock length (mm) | Cut order
Part ID | Part | Part instance | Part length (mm)
Start from usable edge (mm) | End before kerf (mm) | Kerf after this part (mm)
Final remnant (mm) | Remnant class

Cells remain quoted, with formula-like text escaped. This is not a universal guarantee for every spreadsheet import/save mode. Offsets and remnants describe the same approved geometry as the print sheet. Print invokes the browser's print flow; Save as PDF is a browser option, not an additional Offcut tool or a physical cutting transaction.

Use your real browser agent

The challenge permits ChatGPT's built-in browser or Google Chrome with WebMCP enabled. Offcut itself does not supply an agent; host accounts, model availability and permissions are separate from this website's no-login, no-key access.

ChatGPT Site tools — official setup as of September 3, 2026

These are dated host prerequisites from OpenAI's authoritative Site tools guide, not a claim that a ChatGPT desktop session was recorded or verified for this candidate.

  1. Update to the latest ChatGPT desktop app and use its built-in browser with ChatGPT Work or Codex. Select GPT-5.6 Sol or GPT-5.6 Terra; GPT-5.6 Luna currently has WebMCP disabled.
  2. Use a workspace other than Enterprise or Edu: Site tools are not available in those workspaces. Availability also depends on rollout and the current page. Updating the app alone does not guarantee access.
  3. In Settings > Browser > Permissions, ensure Enable site tools is on. Normal website-access and confirmation policies still apply; review consequential actions and keep final approval outside agent UI control if that decision is to remain yours.
  4. Open the live workbench directly in the top-level browser page. Select Site tools in the address bar, then Available site tools to inspect Offcut's six tools. Where available, Recently used opens Sources for recent calls. Ordinary browser/UI fallback actions are not native WebMCP calls.

ChatGPT currently supports top-level JavaScript-registered tools, not declarative form tools or tools in any iframe, including same-origin frames. Offcut uses that top-level imperative path. The built-in browser has a separate profile from your normal browser: establish the sample or your measurements inside this host and keep the same document open through review and export. Closing or navigating away removes that page session's tools, plans and approval. If tools are absent, check model, workspace, rollout, permission and page context against the official guide before interpreting the absence as an Offcut registration failure.

Supported Chrome alternative

In Chrome 149 or later, enable chrome://flags/#enable-webmcp-testing and restart, as described by Chrome's developer guide and the challenge rules. An isolated test-browser launch can use --enable-features=WebMCP. The flag exposes the native API; a configured real browser-agent host must still discover and invoke the tools. Offcut prefers real document.modelContext, with only the actual native navigator.modelContext Chrome-149 compatibility path. It installs no polyfill. Without native support, the complete manual workflow remains available.

Wait for the site's real registration status. “Native WebMCP ready” means registration succeeded, not that a particular model has connected. The activity panel attributes real UI actions and native tool invocations separately.

Physical model and honest result confidence

For every used stock length, Offcut enforces:

sum(finished part lengths) + part count × blade kerf
  + final remnant = usable stock length

Each produced part consumes one saw pass, including the last. No free final factory-end cut is assumed. At a 3 mm kerf, a 997 mm part fits a 1,000 mm usable board; a 1,000 mm part does not fit under this conservative policy. It is not a universal model of every possible end-cut convention.

Positive remnants at or above your threshold are reusable; shorter positive remnants are short scrap; zero is neither. Waste is sawdust plus short scrap. Unopened stock is not waste. For a fixed complete job and kerf, modelled sawdust is constant, so the meaningful trade-offs are stock opened, stock pieces handled and remnant distribution.

The deterministic branch-and-bound search is limited to 100,000 search nodes. “Optimal for this objective” is reported only after valid exhaustive search/pruning with a complete result. At the limit, a feasible plan remains a feasible plan with optimality unproved. Failure to find a complete plan under a search bound is not a proof of infeasibility. Partial proposals identify missing quantities and cannot be approved/exported.

A reused solution is still a new unapproved proposal

Repeating a valid request may reuse a retained checked solution only at the same current revision, objective and canonical additional-exclusion set. Different input order for the same set is equivalent; a different additional set is a different reuse key, even if its overlap with protected stock makes the effective constraints equal. There is no cross-revision reuse.

The new record still receives its own full ID, creation time, actor and activity event, and its solution is independently physically validated. reusedFromPlanId names the actual retained source record; it is null for a new computation. Reuse copies neither the old record nor its approval. UI and native metadata disclose the reuse.

On reuse, search.nodes and optimality/proof status describe the original search, not newly executed nodes or a new proof. A reused bounded solution remains unproved if the original search was unproved. No browser/model latency, workshop time or physical savings claim follows from avoiding a repeated search.

This is a planning estimate, not machine-control, a certified design, or a safe-cutting guarantee. It does not model angled cuts, grain matching, clamping, rough-board defect placement or different material sections. Verify stock identity, usable measurements, actual blade kerf and safe workholding at the bench.

A demonstrated trade-off, not an invented savings claim

The verified 1.1.0 illustrative 14-part job, with A-01 protected, 3 mm kerf and a 400 mm reusable-remnant threshold, reports:

Objective Stock opened Stock pieces Sawdust Short scrap Reusable remnants
Use less stock 7,200 mm 3 42 mm 158 mm 0 mm
Handle fewer boards 7,200 mm 3 42 mm 158 mm 0 mm
Keep useful offcuts 10,080 mm 6 42 mm 0 mm 3,038 mm

All produce the same 7,000 mm of finished parts and keep A-01 untouched. The last plan discards 158 mm less short scrap, but opens 2,880 mm more stock and handles three more lengths. Those are scenario-specific computed results, not measured real-workshop impact, time, money or carbon savings. Later reuse of the remnants is not demonstrated.

Run the source

Source: github.com/ilyanaxo/offcut-webmcp. The project is a static React/TypeScript application built with Vite. Use Bun 1.4 or later and a Node runtime meeting the package's Node 22.12-or-later requirement. 

git clone https://github.com/ilyanaxo/offcut-webmcp.git
cd offcut-webmcp
bun install --frozen-lockfile
bun run build
bun run preview

The production preview is http://127.0.0.1:4173/. For development, bun run dev uses http://127.0.0.1:5173/. No environment secrets are required. Deploy the generated dist/ directory to static HTTPS hosting; relative asset URLs support a project subdirectory.

Run observable-contract checks

bun run test
# Keep the production preview running, then in another terminal:
bun run test:browser
bun run format:check

Browser tests use installed Google Chrome with its sandbox enabled. CHROME_PATH can select a different installed Chrome executable; OFFCUT_BASE_URL can target your HTTPS deployment. The suite does not secretly start a server or install a native-API polyfill. Native and ordinary/manual browser projects are separate.

Browser-test temporary profiles default to .cache/browser-tests in the project. An explicit TMPDIR overrides this location. On systems with per-user quotas on /tmp, choose a private directory on a filesystem with enough actual quota headroom, not just globally reported free space.

The checks defend physical feasibility, quantities, accounting, all three objectives, revision/approval transitions, pending-edit holds, CSV identity/content and the real browser surface. The exhaustive small-instance oracle is independent of the planner; its seeded cases and the earlier smoke use the same corpus, not two independent datasets. Instructions here are not a new pass report. See the source-bound verification records for actual results.

Native API profiles are version-specific

The current 1.1.0 browser checks used Chrome 149.0.7827.155 and 152.0.7977.64. Their native client profile uses a fresh real RegisteredTool from getTools(), including its window/origin, and executeTool(tool, JSON.stringify(input)). Discovered inputSchema values and client inputs are JSON strings; producer registration schemas are objects. Offcut's plain-object callback results return through this client as JSON strings. Do not replace the discovered record with a serialized imitation or silently adopt a different draft's object-input client profile.

Pinned Chromium source declares synchronous undefined registration in 149 and a Promise<undefined> in 152. Offcut's local type permits void | Promise<void>; awaiting registration handles both. The observed callbacks received input only, so execution options remain optional. Current documentation describes broader/newer APIs; that is not proof of another runtime or a ChatGPT desktop recording.

Data, rights and implementation references

Validated measurements are saved in localStorage on this site's origin when available. Plans, approvals, activity, pending editor state and native registration last for the current page session; pending state resets on reload. The website has no application backend or model calls. A browser agent receives tool results and may process them under its provider's policies; hosting/browser policies also apply.

The application source and original visual/example assets use the repository's MIT license. Runtime dependency copyrights and licenses are preserved in THIRD_PARTY_LICENSES.txt. No customer data or copied workshop photographs are used in the illustrative example.

Cutting-stock optimization is established work, not an invention claimed here. OpenCutList, for example, already supports standard/offcut boards, blade thickness, trimming and cutting diagrams. Offcut's contribution is the shared committed workshop, explicit agent comparison, exact review/release and revision invalidation in one browser page—not a claim to be the first cutting optimizer or the first such product worldwide.
